# Dependency security review

Review date: 7 November 2026. This record covers the patched package versions from PR #85 and the runtime dependency cleanup in PR #87. It is a call-path assessment, not a claim that the installed graph has no advisories or that a deployment is accepted.

React Router and its dev/node/serve packages now use the patched 7.18.5 family. Vite stays on major 6 at 6.4.5; PostCSS is 8.5.32. Compatible transitive updates remove the reported critical findings and the applicable Router Framework Mode risks, including [unbounded manifest expansion](https://github.com/remix-run/react-router/security/advisories/GHSA-8x6r-g9mw-2r78). React 18, the Netlify adapter and the Firebase SDK majors remain unchanged. No peer checks are bypassed and no dependency override is used.

The initial full npm audit reported 54 affected package entries: 3 low, 18 moderate, 25 high and 8 critical. After the update it reports 19: 15 moderate and 4 high, with no critical or low entries. These are package and dependency-chain counts, not independent exploits. The remaining entries refer to the six advisories below. PR #85's production-only audit reported 12 entries: 8 moderate and 4 high. PR #87 moves both Firebase SDKs and their exclusive dependencies to development tools, removes unused `currency.js`, and keeps every retained package version. Its production-only audit reports zero entries. The full development graph still reports the same 19 entries and needs the call-path dispositions below.

The public app has no Firebase import path. Historical capture remains an explicit development-only operator command. Inspect both the installed production graph and the freshly built client/server imports before release; a package classification alone does not establish build isolation.

## Remaining advisories

The disposition is **not applicable to the current operations** for each row. The packages remain affected according to npm. Do not treat these dispositions as permission to introduce the affected operations.

| Advisory and affected operation | Installed path and inspected caller | Disposition and recheck trigger |
| --- | --- | --- |
| [gRPC certificate context](https://github.com/grpc/grpc-node/security/advisories/GHSA-m9gg-hp2v-232j): server credentials permit unauthenticated client certificates and the server uses `getAuthContext` for authentication | Firebase Firestore uses `@grpc/grpc-js` 1.9.16 as a **client**. The separate Admin SDK transport uses patched 1.14.7. App and capture code create no gRPC server, server credentials or `getAuthContext` authentication. | The required server operation is absent. Recheck before adding a gRPC server, xDS/RBAC or certificate-based server authentication. |
| [gRPC handler error disclosure](https://github.com/grpc/grpc-node/security/advisories/GHSA-f596-whhp-79r4): a gRPC server sends a crashed method handler's error to its client | Same retained client-only path. The application HTTP handler is not a gRPC server. The Admin transport is patched. | No application gRPC method handler can expose an error through this path. Recheck before adding gRPC service handlers. |
| [UUID buffer bounds](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq): `v3`, `v5` or `v6` writes into a caller-supplied output buffer | The only retained UUID copy is 9.0.1. Its consumers are google-gax 4.6.1, gaxios 6.7.1 and teeny-request 9.0.0. Their inspected calls use `v4()` without output buffers. No app or capture caller imports UUID. | The affected operation is absent; the advisory distinguishes `v4`. Recheck every consumer after an SDK update or before using a UUID output buffer or another UUID method. |
| [esbuild development server CORS](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99): a website reads the esbuild serving API | Drizzle Kit 0.31.11 uses @esbuild-kit/esm-loader → core-utils → esbuild 0.18.20. Core-utils calls `transform` and `transformSync`, not `serve` or `context().serve`. The exposed project command is `drizzle-kit generate`. Vite uses patched esbuild 0.25.12; tsx uses 0.28.2. | The vulnerable server is not started. Local-only serving would not be a sufficient control. Recheck before adding a serving command, changing the loader or using another Drizzle command. Do not downgrade Drizzle Kit to satisfy npm's suggested fix. |
| [glob cancellation bypass](https://github.com/isaacs/node-glob/security/advisories/GHSA-3g3m-2fjr-6pw4): a canceled attacker-influenced traversal continues in the background | glob 10.5.0 is only under Sucrase 3.35.0, a Tailwind dev dependency. Sucrase's CLI imports glob. Tailwind's config loader imports Sucrase's transform API, whose entry point does not import that CLI. No project command invokes the Sucrase CLI or exposes glob traversal to requests. | The affected traversal is not part of the build or runtime path. Recheck before adding the CLI, globbing, request-controlled patterns, directory trees or cancellation budgets. |
| [minimatch pattern amplification](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249): attacker-controlled preprocessing patterns expand with optimization level 2 or higher | minimatch 9.0.9 is only under that glob/Sucrase CLI path. npm flags 7.x–11.0.0; the maintainer describes a 10.2.6 example. This disposition does not depend on that version-range difference: the CLI path is not invoked and no public pattern reaches it. | Recheck before exposing pattern matching, invoking the CLI, changing optimization options or moving this tooling into runtime. |

The four high npm entries are `@grpc/grpc-js`, `@firebase/firestore`, `@firebase/firestore-compat` and `firebase`, all from the retained server-only gRPC advisories above. The moderate entries are the Drizzle loader chain (four), glob/minimatch/Sucrase (three), and UUID/Google SDK chain (eight). No package entry is omitted from this disposition.

## Release check

The release maintainer must rerun `npm audit --json`, `npm audit --omit=dev --json` and `npm ls --all` against the exact release lock before promotion. Inspect every new advisory and every changed caller. An applicable defect blocks release; a package's severity alone does not establish its reachable operation. Refresh this record when a trigger above occurs. Do not replace the record with a blanket audit exclusion or an incompatible major override.

Verification for this change includes clean `npm ci`, peer validation, tests, typecheck, build, actual installed Firestore transport codecs, local migration/import/replay, preserved values and PDF bytes, built HTTP document and private queue checks, and browser hydration checks. Local results and independent review evidence are recorded separately. Offline SDK checks do not verify ADC, IAM, complete administrative export or restore. Those remain cutover gates. Live staging isolation, deployment and explicit user acceptance remain required under [develop acceptance](develop-acceptance.md).
